2. Models currently being used
Structured K model

Current lineage:

mlb-k-v0.8.2-independent-target-market-2026-09-06

This is now the cleanest model in the project.

Step A — workload

PropsMadness supplies:

Pitcher Outs
Earned Runs
Hits Allowed
Walks

Those are converted into expected workload and ultimately:

Expected Batters Faced

The model therefore doesn't simply ask, "What is this pitcher's K rate?" It first asks how many realistic strikeout opportunities he'll receive.

Step B — pitcher skill

Baseball Savant supplies the starter's:

K%
Whiff%
Swing%
BB%

We derive:

Contact% = 100 − Whiff%

and

SwStr% = Swing% × Whiff%

Step C — actual opposing batting order

MLB Official supplies the nine published hitters.

Savant supplies those hitters' actual underlying K/Whiff/Swing-type skill data.

The model calculates lineup-weighted opponent tendencies rather than treating every team as a generic season average.

PropsMadness opponent ranks such as:

K rank
Whiff rank
Contact rank
Chase rank
BB rank
Pitches/PA rank
xwOBA rank
HardHit rank

remain useful context, but we deliberately do not turn ordinal ranks like #7 K% into made-up percentages.

Step D — structural expected K

Conceptually:

Expected BF × matchup-adjusted K probability = structural expected K

The matchup probability combines the pitcher's underlying strikeout/whiff/contact skill with the actual opposing lineup.

Step E — independent blend

The current blend is:

Component	Weight
Structural K	70.51%
Recent K performance	19.23%
Season K/start	10.26%
Target K market	0.00%

That last line is crucial.

The sportsbook's K line and price cannot move expected K.

Step F — distribution

Expected K is converted into an overdispersed Poisson distribution.

So instead of merely saying:

Expected K = 5.8

we can calculate:

P(Over 4.5)
P(Over 5.5)
P(Over 6.5)
fair price
EV at a listed sportsbook price

without rebuilding expected K.

Step G — market comparison

Only after the distribution exists does PropsMadness supply:

current K line
Over odds
Under odds
sportsbook
timestamp

If both sides exist, MODEL removes the vig and calculates:

Model probability − local no-vig probability = edge

It also calculates EV against the actual listed price.

If only one side exists, we can calculate EV on that side, but we do not invent a no-vig market probability.

Current K validation status

PROSPECTIVE_INPUT_MIGRATION

Therefore even an otherwise excellent K edge is currently capped at WATCH until we accumulate enough forward evidence to validate this new input architecture.

4. Trust Layer

Trust states are:

VERIFIED — all required integrity/market/model gates pass and the edge is actionable.

WATCH — potentially useful but one or more confidence limitations remain.

PASS — model worked, but edge/EV isn't sufficient.

ANOMALY — model and market disagree by an unusually large amount and should be investigated instead of blindly bet.

BLOCKED — required identity/data/freshness/market information failed.

# MODEL PHILOSOPHY

The core philosophy is:

**BASEBALL DATA → INDEPENDENT PROBABILITY → MARKET COMPARISON → TRUST**

Sportsbook prices must NOT manufacture the model prediction.

The model should determine fair value independently and only afterward ask:

“What price is the market offering?”

This separation is non-negotiable.

Fail closed when trustworthy inputs are unavailable.

Large apparent edges are not automatically good bets. They may represent:

* bad inputs
* identity errors
* workload uncertainty
* small-sample problems
* market disagreement
* genuine model misspecification

Trust exists to distinguish those cases.

### K v0.8.3 HARDENING

Pivetta exposed a major issue on Sep 7:

* MODEL projected Pivetta xK ~6.22

* confidence High
* he finished with only 2 Ks

2. otherwise a league prior

* K%

Workload states include concepts such as:

* NORMAL
* LIMITED
* OPENER_LIKE
* UNANCHORED

A Pivetta-like 66-BF + limited-workload case can no longer remain clean `High` confidence.

The raw mathematical signal may still exist, but Trust can block it.

# WORKLOAD INTEGRITY

Burns exposed another issue.

Previously ML could use season-average Pitcher Outs as production workload even when the current game had special workload management.

That is now fixed.

Production ML requires a trustworthy **current-game workload anchor**.

Season-average workload can still be used by:

* Slate Radar
* diagnostics

but should NOT silently qualify a production ML prediction when current workload is uncertain.

Special contexts we want increasingly represented:

* returning from IL
* pitch limit
* piggyback
* opener
* September workload management
* rehab return
* workload unknown

If credible restriction exists but exact magnitude is unknown, prefer:
`WORKLOAD_UNCERTAIN / BLOCKED`
rather than inventing precision.

# TRUST PHILOSOPHY

Statuses conceptually mean:

VERIFIED:
production inputs complete, market comparison valid, discrepancy acceptable, useful edge

WATCH:
interesting but not fully verified/calibrated

PASS:
model valid but insufficient edge/EV

RESEARCH ANOMALY:
model-market disagreement too large; investigate rather than blindly bet

BLOCKED:
required trustworthy input unavailable

Trust should protect us from false confidence.
